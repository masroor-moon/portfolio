Learning Journal

Reading Linux login logs

14 November 2026 | Topic: Linux logs

What I learned: Linux keeps a record of login attempts in the file /var/log/auth.log. With the command "sudo tail -n 20 /var/log/auth.log" I could read the last 20 lines and see failed password checks followed by a successful login. I also learned that "grep" can search a log file for a keyword, which helps find failed logins quickly.

Challenge: My first search, grep "authentication failure", showed only my own sudo commands and not real failed logins. The log also records the commands I type, so my search was finding itself.

How I solved it: I ran "sudo -k" so that sudo would ask for my password again, and then entered three wrong passwords on purpose. After that I used grep "authentication failure" together with grep -v "COMMAND=" to remove my own command lines. This showed a real failed sudo login at 14:43.

What I could improve: I expected three lines for three wrong attempts but saw only one. My guess is that sudo records the three attempts together in a separate line, and my filter removed it, but I have not confirmed this yet. Next time I will also search for "incorrect password" and compare both results.

Fixing a broken menu link

20 November 2026 | Topic: HTML links

What I learned: A link to a section on the same page needs a # sign before the id, for example href="#education". The id on the section and the name in the link must match exactly.

Challenge: When I clicked Education in my menu, the browser showed "Cannot GET /education" instead of moving to the Education section.

How I solved it: I checked the menu code and found that the # sign was missing, so the browser was looking for a separate page called /education. After I got an explanation from an AI tutor and added the # sign, the link worked. I tested it again by clicking it, and then saved the fix as a new commit on GitHub.

What I could improve: I pushed the mistake to GitHub before testing it. From now on I will click every new menu link in the browser before I commit.

Setting up Git and my first push to GitHub

20 November 2026 | Topic: Git and GitHub

What I learned: Git saves the history of my project, and GitHub keeps a copy online. I learned the basic steps: git init, git add, git commit, and git push. A commit is a saved snapshot of my files with a short note about what changed.

Challenge: When I typed "git --version" in the VS Code terminal, it said that "git" is not recognized. Git was not installed on my laptop yet.

How I solved it: I downloaded Git from the official website, installed it, and restarted VS Code. Then "git --version" worked. After that I set my name and email, connected my folder to my GitHub repository, and pushed my first commit. I also renamed the branch from master to main so it matched GitHub.

What I could improve: I want to write clearer commit messages and commit after each finished section, so that my history shows my progress step by step.
